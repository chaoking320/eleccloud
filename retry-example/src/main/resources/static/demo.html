场景1：电商退款
注解模式 · sceneType=10 · FIXED 5秒
业务层调用模拟支付宝退款API，API 前 N 次返回"连接超时"。 @RetryableTask AOP 自动捕获异常并提交重试任务， 无需任何手动代码，最侵入性最低。
@RetryableTask(sceneType = 10, idempotentKey = "#transId")
public void refund(String transId, ...) {
  // 调用下游支付宝接口（可能超时）
  restTemplate.postForObject("/mock-api/payment/refund", ...);
  // 抛异常 → AOP 自动提交重试任务
}

public boolean settle(String transId, ...) {

场景3：库存同步
预提交模式 · sceneType=12 · FIXED 5秒
业务层调用模拟 WMS 仓储同步接口。preSubmit=true： 方法执行前先注册任务，即使进程在执行中途被 kill -9 也不会丢失， 适合强一致性场景。
@RetryableTask(sceneType = 12, idempotentKey = "#transId",
                preSubmit = true) // 执行前先注册！
public void syncInventory(String transId, ...) {
  restTemplate.postForObject("/mock-api/warehouse/inventory/sync", ...);
  // 成功后 AOP 自动调用 markSuccess()
}
