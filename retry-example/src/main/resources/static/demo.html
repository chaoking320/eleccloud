场景1：电商退款
注解模式 · sceneType=10
就绪
模拟支付宝退款。业务方法仅需配置 @RetryableTask，异常触发时 AOP 自动上报任务并触发 Hook 状态机，无需编写手动补偿代码。
@RetryableTask(sceneType = 10, idempotentKey = "#transId")
public void refund(String transId, ...) {
  alipayClient.execute(request);
}

场景2：酒店结算
API 模式 · 精细化重试
就绪
调用 OTA 结算接口。在业务 catch 块中手动调用 retryClient.submit()，按异常类型（如仅在网关繁忙时重试，参数错误则放弃）。
try {
  otaClient.doSettlement(req);
} catch (GatewayBusyException e) {
  retryClient.submit(retryReq);
}
SUBMIT → WAIT → SUCCESS

场景3：库存同步
预提交模式 · preSubmit=true
就绪
WMS 仓储同步。方法执行前先向平台预注册任务，即使执行期间遭遇机器断电或 kill -9 宕机，任务永不丢失。
@RetryableTask(sceneType = 12, preSubmit = true)
public void syncInventory(String sku) {
  wmsClient.sync(sku);
}
PRE_SUBMIT → EXECUTE → DONE

场景4：双层混合重试
本地快速 200ms + 分布式平滑升级
就绪
新特性落地：通过 localRetryTimes = 2 先在当前进程内 200ms 快速消化偶发抖动（零分布式开销）；若依然失败，则平滑升级为服务端集群调度。
@RetryableTask(sceneType = 10,
  localRetryTimes = 2, localIntervalMs = 200)
public String sendSms(String msgId, ...)
本地重试 → 快速恢复 → 分布式升级
